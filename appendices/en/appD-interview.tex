\chapter{Twenty interview problems, solved in both languages}
\label{app:interview}

\noindent
These are the kind of problem a Python interview actually asks: small
enough to write on a whiteboard, big enough that the idiomatic answer
differs from the one a C\# engineer reaches for first. Each is solved twice
\dash{} once in Python, once in C\# \dash{} and both answers are compiled,
run and asserted by CI against the same cases. A worked answer in a book
that nobody runs is the thing this book exists to refuse.

Read the pairs for the shape rather than the line count. Where the Python
is shorter it is usually because the standard library has the step already;
where the C\# is shorter it is usually because a type made something
explicit. Neither is a scoreboard. The rows worth slowing down for are the
three where the two languages give \emph{different answers} to the same
input unless you write the correction: rotation's modulo, binary search's
return contract, and the ragged matrix.

\csregion{code/csharp/Solutions/Interview/Problems.cs}{rotate}{C\#}{lst:appD-rotate-cs}

\noindent
The modulo is the whole problem, and it is the sharpest divergence in this appendix.
