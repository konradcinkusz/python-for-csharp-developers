\chapter{Traps for people arriving from C\#}
\label{app:traps}

\noindent
Every habit below compiles in your head. That is what makes them traps
rather than mistakes: each one is a correct instinct about C\# applied to a
language where it is wrong, and most of them produce Python that runs. The
book puts each to you before naming it, in the chapter that owns it; this
appendix is the list you come back to.

Two things about the numbering, because it is load-bearing. **A number is
never reused**, so a chapter that cites one is citing the same entry for
ever \dash{} which is why the list is not in numeric order within a part,
and why some numbers are in the hundreds. And **each entry names the
chapter that elicits it**, so every line here is a claim about the book
that can be checked by opening that chapter.

\section{Part I \dash{} Runtime and toolchain}
\label{sec:appB-part1}

\trapentry{1}{Threads are useless in Python, so I will not bother with
them.}{The lock serialises \emph{bytecode}; a thread blocked on I/O holds
no lock. Threads are the right tool for I/O-bound work and the wrong one
for CPU-bound work, and experiment E1 measures both.
Chapter~\ref{ch:runtime}.}

\trapentry{2}{The interpreter is free-threaded now, so the lock is
gone.}{The free-threaded build is a separate binary, \code{python3.14t},
and you opt into it. The default build still has the lock.
Chapter~\ref{ch:runtime}.}

\trapentry{3}{Python has no compile step, so there is nothing like
IL.}{Source is compiled to bytecode and cached in \code{\_\_pycache\_\_};
\api{dis.dis} on a function shows it. There is no JIT you can count on by
default. Chapter~\ref{ch:runtime}.}

\trapentry{4}{\code{if \_\_name\_\_ == "\_\_main\_\_"} is
boilerplate.}{It is the difference between a module that runs when it is
imported and one that runs when it is executed \dash{} the reason a listing
in this book can be both importable and runnable.
Chapter~\ref{ch:runtime}.}

\trapentry{5}{\code{pip install} puts the package on the machine, like a
global tool.}{An environment is a directory. A global install is the one
thing every later chapter's listings cannot survive.
Chapter~\ref{ch:packaging}.}

\trapentry{6}{I activate the environment and then run things.}{\code{uv
run} resolves the environment per invocation. Activation is the habit that
ships the wrong interpreter to CI. Chapter~\ref{ch:packaging}.}

\trapentry{7}{\code{requirements.txt} is the lockfile.}{It is a wish list
with ranges. \code{uv.lock} is the lockfile, it is committed, and
\code{uv sync --locked} refuses to drift from it.
Chapter~\ref{ch:packaging}.}

\trapentry{8}{A type hint is a type.}{It is a claim the runtime never
checks: a parameter annotated \code{str} can be \code{None} at run time and
nothing says so. A checker is a second compiler you have to invite.
Chapter~\ref{ch:typing}.}

\trapentry{9}{\code{List[int]}, \code{Optional[str]},
\code{Dict[str, Any]}.}{Those are the 2019 spellings. On the pinned
interpreter it is \code{list[int]}, \code{str | None} and
\code{dict[str, Any]}, with PEP~695 syntax for generics.
Chapter~\ref{ch:typing}.}

\trapentry{10}{\code{@dataclass} validates its fields, like a record with a
constructor.}{It generates \code{\_\_init\_\_}, \code{\_\_eq\_\_} and
\code{\_\_repr\_\_} and checks nothing. Validation at a boundary is
pydantic's job. Chapter~\ref{ch:typing}.}

\trapentry{11}{\code{def f(items=[])} \dash{} an optional list
parameter.}{The default is evaluated once, at definition, and shared by
every call that does not pass one. Default to \code{None} and construct
inside. Chapter~\ref{ch:typing}.}

\trapentry{12}{\code{Any} is like \code{dynamic}: a thing I can
contain.}{\code{Any} propagates. One \code{Any} in a chain turns everything
downstream into \code{Any}, and the checker reports nothing at all.
Chapter~\ref{ch:typing}.}

\section{Part II \dash{} The language, mapped}
\label{sec:appB-part2}

\trapentry{13}{Override \code{\_\_eq\_\_} and I have value equality, like
overriding \code{Equals}.}{Defining \code{\_\_eq\_\_} sets
\code{\_\_hash\_\_} to \code{None}: the object becomes unhashable and
cannot be a \code{dict} key or a \code{set} member. C\# warns (CS0659) and
carries on; Python acts. Chapter~\ref{ch:objects}.}

\trapentry{14}{\code{is} is reference equality, so \code{x is 5} is fine
for small integers.}{Two mechanisms, and the folklore names only one.
CPython caches the integers \code{-5} to \code{256}; independently of that,
the compiler stores equal constants once per code object, so two literal
\code{257}s in one function are also one object. The classic demonstration
therefore does \emph{not} reproduce in a script, and the bug appears only
once a value has crossed a run-time boundary. Keep \code{is} for
\code{None} and sentinels. Chapter~\ref{ch:objects}.}

\trapentry{15}{\code{[[]] * n} gives me \code{n} lists.}{It gives one list
\code{n} times, because \code{*} copies the reference.
\code{[[] for \_ in range(n)]} gives \code{n}. Chapter~\ref{ch:objects}.}

\trapentry{16}{A class attribute is a static field.}{It is shared by every
instance \emph{and} readable through them, so a mutable class attribute
mutated through \code{self} is mutated for everyone.
\code{@dataclass} refuses the spelling it can see; the plain-class spelling
is the one it cannot. Chapter~\ref{ch:objects}.}

\trapentry{17}{\code{\_\_str\_\_} is \code{ToString()}.}{\code{\_\_repr\_\_}
is what the debugger, the REPL and a \emph{list} of the objects show.
\code{\_\_str\_\_} is what \code{print} shows, and it falls back to
\code{\_\_repr\_\_}; the reverse is not true.
Chapter~\ref{ch:objects}.}

\trapentry{18}{\code{0.1 + 0.2 == 0.3} is a Python bug.}{It is IEEE~754 in
both languages, and since .NET Core~3.0 both even print it the same way,
as \code{0.30000000000000004}. Use \api{math.isclose} for computed floats
and \api{decimal.Decimal} for money. Chapter~\ref{ch:objects}.}

\trapentry{19}{\code{/} on two integers is integer division, as in
C\#.}{\code{/} is true division. \code{//} floors, and floors towards
negative infinity, which \code{-7 // 2 == -4} demonstrates; C\#'s answer is
Python's \code{int(a / b)}. Chapter~\ref{ch:objects}.}

\trapentry{20}{A decorator is an attribute \dash{} metadata a framework
reads.}{A decorator is a function that runs at definition time and can
replace what it decorates. It is middleware, not metadata.
Chapter~\ref{ch:functions}.}

\trapentry{21}{A comprehension is LINQ.}{A list comprehension is eager
where \code{IEnumerable} is deferred, and a generator expression is
deferred \emph{and single-pass}, where a LINQ query re-runs on every walk.
Materialise once, on purpose. Chapter~\ref{ch:functions}.}

\trapentry{22}{A closure in a loop captures the loop variable's
value.}{It captures the variable, late-bound, so every closure sees the
last value. Bind with a default argument or \api{functools.partial}.
Ruff's B023 catches it, which makes this the one trap in that chapter the
toolchain finds for you. Chapter~\ref{ch:functions}.}

\trapentry{23}{\code{s += piece} in a loop is fine; strings are
strings.}{On CPython the plain loop is \emph{linear}: the interpreter
carries a specialisation that resizes in place when the left operand has no
other reference. It is quadratic again the moment anything else holds a
reference \dash{} a list, a closure, an attribute \dash{} with nothing at
the call site changed. \code{"".join(pieces)} has no bad case.
Chapter~\ref{ch:functions}.}

\trapentry{24}{A generator is \code{yield return}.}{It is, including the
\code{finally} that runs on early exit, which is \code{IEnumerator.Dispose}.
It also has \code{send()}, \code{close()} and a return value carried out
\dash{} a coroutine before \code{async} existed, which is why
\code{Generator} has three type parameters where \code{IEnumerable} has
one. Chapter~\ref{ch:functions}.}

\trapentry{140}{\code{case ACTIVE:} compares against the constant, as a
\code{switch} arm does.}{A bare name in a pattern \textbf{captures}: it
binds every subject to \code{ACTIVE} and the arm always matches. The
compiler refuses it when another case follows, so it compiles in silence
only as the last case \dash{} which is exactly where it survives review.
Use a dotted name or a guard. Chapter~\ref{ch:functions}.}

\trapentry{25}{\code{except:} catches everything, like \code{catch
\{\}}.}{It catches \code{KeyboardInterrupt} and \code{SystemExit} too,
which is why the process cannot be stopped. Use \code{except Exception:} at
most, and log the traceback. Ruff reports it as E722.
Chapter~\ref{ch:errors}.}

\trapentry{26}{Catch \code{Exception}, log it, carry on \dash{} it is
defensive.}{It converts a crash into a silent wrong answer. EAFP means
catching the exception you expect, not every one. This is the one trap in
that chapter nothing in the book's toolchain reports, which is why it is
the one that reaches production. Chapter~\ref{ch:errors}.}

\trapentry{27}{\code{raise e} inside \code{except} re-throws, like
\code{throw ex;}.}{Python keeps the traceback on the exception
\emph{object}, so \code{raise e} truncates nothing: every frame under it
survives and the re-raise line is \emph{added}. Bare \code{raise} is still
the better habit, because the duplicate frame is noise, but the C\# rule
does not transfer. What a re-raise can lose is the link: without
\code{from}, \code{\_\_cause\_\_} stays \code{None}.
Chapter~\ref{ch:errors}.}

\trapentry{28}{\code{return} in \code{finally} is harmless.}{It swallows
any in-flight exception and returns as if nothing had happened. Not
silently on the pinned interpreter \dash{} PEP~765 has the compiler emit a
\code{SyntaxWarning}, and ruff reports B012 and SIM107 \dash{} but it still
swallows, because a warning is not an error. Chapter~\ref{ch:errors}.}

\trapentry{29}{A method's hint tells me what it raises.}{Nothing in the
type system carries exceptions. A docstring does, and nothing verifies it.
Python has no checked exceptions \dash{} nor does C\#, so what transfers
badly is the tooling rather than the language. Chapter~\ref{ch:errors}.}

\trapentry{30}{\code{KeyError} means something went wrong.}{\code{KeyError},
\code{StopIteration} and \code{AttributeError} are protocol: a \code{dict}
lookup, an iterator's end and \api{getattr} all speak through them.
Chapter~\ref{ch:errors}.}

\trapentry{31}{Truthiness is \code{bool}, as in C\#.}{Empty containers,
zero, \code{None} and empty strings are all false. \code{if items:} is
idiomatic, and \code{if items is not None:} asks a different question.
Chapter~\ref{ch:errors}.}

\trapentry{150}{An exception class is a \code{FooException}.}{Python's
suffix is \code{Error}, and ruff's N818 reports a class without it:
\code{JobUnavailable} fails the lint until it is
\code{JobUnavailableError}. Chapter~\ref{ch:errors}.}

\trapentry{32}{A module is a namespace, so importing it is free and
pure.}{A module is an object that runs once, top to bottom. A side effect
at import runs for every importer, and a circular import is two modules
half-run. Chapter~\ref{ch:imports}.}

\trapentry{33}{\code{from x import *} is \code{using x;}.}{It copies every
public name into the importing module and hides where anything came from.
Use \code{import x}, or \code{from x import name}.
Chapter~\ref{ch:imports}.}

\trapentry{34}{I can name a variable \code{list}, \code{id} or
\code{type}.}{It shadows the builtin for the rest of the scope, and the
failure arrives three functions later. Chapter~\ref{ch:imports}.}

\trapentry{35}{I need a DI container.}{A composition root is a function.
\api{functools.partial} and a \code{Protocol} do what the container did,
and FastAPI's \code{Depends} is the one container most readers will meet.
Chapter~\ref{ch:imports}.}

\section{Part III \dash{} Concurrency}
\label{sec:appB-part3}

\trapentry{36}{A coroutine is a \code{Task}: calling it starts it.}{A
coroutine is cold. Calling it builds an object that does nothing until it
is awaited or scheduled, and forgetting the \code{await} is a warning
rather than an error. Chapter~\ref{ch:asyncio}.}

\trapentry{37}{\code{create\_task} starts the task immediately.}{It
schedules it; the body does not run until the caller yields.
Chapter~\ref{ch:asyncio}.}

\trapentry{38}{\code{.Result} on a task deadlocks, so I use
\code{ConfigureAwait(false)}.}{There is no synchronisation context and no
\code{ConfigureAwait}. There is one loop, and one blocking call inside it
freezes every other coroutine, with no error and no log line.
Chapter~\ref{ch:asyncio}.}

\trapentry{39}{\code{gather} is \code{WhenAll}.}{\code{gather} orphans its
siblings when one fails; \code{TaskGroup} cancels them. The two are
identical on speed, so the choice is only ever about failure semantics.
Chapter~\ref{ch:asyncio}.}

\trapentry{40}{Cancellation is a token I poll, so catching
\code{Exception} is how I lose it.}{Backwards in both halves. It is
\code{CancelledError}, delivered at an \code{await}, and it inherits from
\code{BaseException} \dash{} so \code{except Exception} is the clause that
lets it \emph{through}. What swallows it is a bare \code{except:},
\code{except BaseException:}, or an \code{except asyncio.CancelledError}
block with no \code{raise} under it. Chapter~\ref{ch:asyncio}.}

\trapentry{41}{\code{HttpClient} is a singleton, so
\code{httpx.AsyncClient} is too.}{The lifetime advice carries \dash{}
construct it once, share it, close it \dash{} and the defaults do not: a
default client already has a five-second deadline, applied separately to
connect, read, write and pool rather than to the request as a whole.
Chapter~\ref{ch:asyncio}.}

\trapentry{170}{A \code{Task} can be awaited twice, so a coroutine
can.}{A \code{Task} is a handle on work already running and hands out its
result as often as you ask. A coroutine \emph{is} the work, and awaiting it
a second time raises \code{RuntimeError}. Chapter~\ref{ch:asyncio}.}

\section{Part IV \dash{} Shipping}
\label{sec:appB-part4}

\trapentry{42}{\code{Depends} is the DI container, so a dependency is a
singleton.}{It is per-request by default. A \code{yield} dependency is a
disposable scope, and application-lifetime state goes in the lifespan.
Chapter~\ref{ch:services}.}

\trapentry{43}{A validation failure is a 400 with
\code{ProblemDetails}.}{It is a 422 with pydantic's error list, and the
shape is pydantic's rather than the framework's.
Chapter~\ref{ch:services}.}

\trapentry{44}{Settings come from \code{IOptions<T>} and
\code{appsettings.json}.}{\pkg{pydantic-settings} reads the environment, a
\code{.env} file and a secrets directory into a validated model. There is
no JSON provider chain. Chapter~\ref{ch:services}.}

\trapentry{45}{More uvicorn workers is more throughput.}{Workers are
processes: each has its own loop, its own pool and its own memory. E5
measured it, and for an awaited upstream four workers moved throughput by
nothing while multiplying the memory. Chapter~\ref{ch:services}.}

\trapentry{180}{Middleware runs in the order I registered it, so the
first one is the outer one.}{The last one registered is the outermost:
starlette's \code{add\_middleware} inserts at the front of the stack.
Nothing warns, and the two orders differ only when something depends on the
sequence. Chapter~\ref{ch:services}.}

\trapentry{181}{\code{Field(alias=...)} is \code{JsonPropertyName}: it
renames the field on the wire.}{It renames it on the way \emph{in} as well,
so the model can no longer be constructed by field name \dash{} and a type
checker says so before the test does. \code{serialization\_alias} is the
output-only one. Chapter~\ref{ch:services}.}

\trapentry{182}{\code{--workers 4} spreads my traffic over four
processes.}{Workers share one listening socket, and the worker that is in
\code{accept()} first keeps the connection for its whole life, so balancing
happens per \emph{connection} rather than per request.
Chapter~\ref{ch:services}.}

\trapentry{46}{A \code{Session} is a \code{DbContext}, so I
\code{commit()} and the objects stay usable.}{\code{expire\_on\_commit} is
true by default, so every attribute is reloaded on next access \dash{}
which is a query inside a loop you did not write.
Chapter~\ref{ch:data}.}

\trapentry{47}{Relationships are loaded when I read them, as in EF.}{Lazy
by default in both, under a \emph{synchronous} session, and the N+1 is
identical; \code{selectinload} is \code{Include}. Under the asynchronous
session the same read raises \code{MissingGreenlet} rather than loading, so
the bug is loud there and silent here. Chapter~\ref{ch:data}.}

\trapentry{48}{Alembic autogenerate is the migration.}{It is a diff of the
models against the database, and it misses renames, type changes and
constraints. A rename comes out as an add plus a drop, which loses the
data. Read every generated migration. Chapter~\ref{ch:data}.}

\trapentry{49}{I need a repository over the ORM.}{The \code{Session} is
the unit of work, and the repository pattern doubles it.
Chapter~\ref{ch:data} says why that is usually a mistake here.}

\trapentry{50}{A test class per fixture, like
\code{IClassFixture}.}{pytest fixtures are functions with a scope. The
class is optional and usually absent. Chapter~\ref{ch:testing}.}

\trapentry{51}{Mock where the thing is defined.}{Patch where the name is
\emph{looked up} \dash{} the importing module \dash{} or the patch does
nothing and the test passes for the wrong reason. Which name the call
resolves was decided by the import, so \code{import x} followed by
\code{x.y()} really is patched at \code{x.y}.
Chapter~\ref{ch:testing}.}

\trapentry{52}{\code{assert} is for debug builds.}{pytest rewrites
\code{assert} to explain itself; it is the assertion library. Half of the
habit is right: under \code{-O} an \code{assert} in the \emph{application}
really does vanish, so it is for tests and invariants and never for
validating input. Chapter~\ref{ch:testing}.}

\trapentry{200}{A test report is a test report; the same failure prints
the same thing everywhere.}{pytest reports differently on a build server,
on purpose: several call sites ask whether \code{CI} or \code{BUILD\_NUMBER}
is set, and a sequence diff is then printed in full and long output is not
truncated. A transcript, a golden file or a screenshot of a failure is a
claim about one of the two machines. Chapter~\ref{ch:testing}.}

\trapentry{53}{\api{logging.basicConfig} and I am done.}{The standard
module's configuration is global and import-order-sensitive, and a second
call is a silent no-op. That is the reason structlog exists.
Chapter~\ref{ch:observability}.}

\trapentry{54}{Correlation id in a static field, like
\code{AsyncLocal}.}{\api{contextvars} is \code{AsyncLocal}. A module-level
variable is shared by every request on the loop.
Chapter~\ref{ch:observability}.}

\trapentry{55}{\code{FROM python} and \code{pip install} in the
Dockerfile.}{Multi-stage, with \code{uv sync --frozen --no-dev}, a
non-root user and the two environment variables.
Chapter~\ref{ch:observability}.}

\section{Part V \dash{} Python for AI work}
\label{sec:appB-part5}

\trapentry{56}{The SDK is magic.}{Every AI SDK is a pydantic model, an
httpx client and a streaming iterator. Read the installed, pinned package.
Chapter~\ref{ch:aitoolkit}.}

\trapentry{57}{\code{model\_validate\_json} is
\code{JsonSerializer.Deserialize}.}{Lax mode coerces where
\code{System.Text.Json} refuses; strict mode is what a C\# engineer
expects, and E8 prices both \dash{} at nothing.
Chapter~\ref{ch:aitoolkit}.}

\trapentry{58}{A notebook is where Python happens.}{A notebook is a REPL
with a memory of every cell you ran in any order. Nothing in this book is
one, and Chapter~\ref{ch:aitoolkit} says when one is right.}

\trapentry{220}{The SDK uses the \pkg{httpx} I pinned.}{Both SDKs depend
on the \pkg{httpx2} distribution rather than \pkg{httpx}, so an
\api{isinstance} check against the one you pinned is \code{False} on a
client that is obviously an httpx client. Of the two SDKs one refuses a
mismatched client and the other accepts it.
Chapter~\ref{ch:aitoolkit}.}

\trapentry{59}{A trace assertion needs a model to evaluate.}{The first
layer of the instrument this book ports is deterministic: it runs with no
model, which is exactly why it can run in CI.
Chapter~\ref{ch:traceassert}.}
