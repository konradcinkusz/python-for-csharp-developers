Why

A C# engineer who starts writing Python does not lack a language course. They have a mental model that is mostly right and wrong in a few specific places, and the places are where the incidents come from: a coroutine that is cold where a Task is hot, a type hint the runtime never checks, an __eq__ that quietly makes an object unhashable, an environment that is a directory rather than a machine setting.

So this is not a Python-from-zero course, not a library catalogue and not another AI book. It is a translation dictionary from C# to Python plus a field manual for shipping Python to production. Each chapter maps one thing the reader already knows onto its Python counterpart, elicits the habit that breaks, and ends with exercises whose tests run in CI on the pinned versions.

Where it sits

It is volume zero of a trilogy. The LangChain, LangGraph and Async Python book is written for the engineer arriving from .NET and assumes the language and the toolchain; this book supplies them and stops where that one starts. Agent frameworks stay there, and Microsoft Agent Framework for .NET Engineers covers the .NET side. Where a topic is owned by one of the other two, this book points there in one sentence and does not repeat a section.

Every chapter is written to be publishable on its own, under three thousand words, with its listings executed in CI against pinned versions. A listing nobody has run carries a marker that says so, and the marker is counted on every build.

The guiding project

trace-assert: a Python port of the first layer of agent-eval-bench, deterministic assertions over an execution trace, in pytest. It starts as a two-record skeleton in Chapter 11, records a model call in Chapter 13, and is completed, packaged and compared with its .NET and TypeScript ports in Chapter 14. The book's own CI has been running it since the scaffold.
